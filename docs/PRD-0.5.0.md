# CleanNest 0.5.0 产品需求：洞察闭环

状态：实现完成，候选验证中

目标版本：0.5.0

版本主题：从“列出占用”升级为“解释、判断、执行后验证，并在用户确认后学习”

## 一句话产品定义

CleanNest 帮助磁盘空间紧张的 Mac 用户在一个本机工作流中看见空间去了哪里、理解内容由什么产生、判断是否值得处理，并通过可恢复操作和可撤销规则完成闭环。

## 用户问题

0.4.x 已能扫描、展示确定性证据和调用可替换本机模型，但仍存在四个明显断点：

1. 大目录首次扫描需要等待完整结果，重复扫描没有充分利用未变化的数据。
2. “用途、来源、可恢复性”散落在长列表中，用户仍需自己拼出结论。
3. 本机学习会记录偏好，但缺少“待审核规则 → 启用 → 暂停/撤销”的完整控制面。
4. 视觉仍以通用卡片堆叠为主，任务状态、下一步和证据层级不够鲜明。

## 成功路径

`发现空间占用 → 解释是什么 → 判断能否处理 → 安全执行 → 验证实际结果 → 提议可复用规则 → 用户审核`

模型只参与“补充解释”；目录身份、清理边界、风险下限、选择、文件操作和验证均由本机确定性逻辑控制。

## P0 范围

### 1. 智能磁盘 2.0

- 原生扫描按顶层项目持续返回部分结果，不必等待整层结束。
- 用户可取消扫描；取消后保留上一次完整结果，不把部分结果冒充完整结果。
- 保存有界的本机扫描索引。只在元数据签名匹配且缓存仍新鲜时复用；手动“深度刷新”必须绕过缓存。
- 明确展示缓存命中、实扫项目、耗时和结果新鲜度，不把缓存值表述为实时实测。
- 索引不得包含文件正文；只保存当前层名称、哈希身份、大小、类型、签名和时间。

量化目标（在同一台 Mac、同一目录、无内容变化的约定环境中测量）：

- 首个部分结果尽量在 3 秒内出现。
- 取消请求在 1 秒内反映到界面；底层递归检查在最近的取消检查点停止。
- 重复扫描较首次完整扫描至少快 70%；若目录发生变化或缓存超时，允许回退为实扫并如实标注。

### 2. 清理决策中心

每个磁盘条目必须形成一份确定性决策摘要：

- 它通常是什么；
- 由谁或什么流程产生；
- 为什么可能变大；
- 当前允许的动作边界；
- 处理后的影响；
- 是否可恢复或重新生成；
- 支撑结论的本机证据和观察局限。

条目分为“可逐项复核”“建议在所属 App 管理”“建议保留/继续查看”。未知内容默认保留。磁盘浏览继续只读，不从任意目录直接删除。

### 3. 可审计的本机学习

- 用户选择“以后优先清理/保留”时先生成待审核提案，不立即改变排序。
- 提案显示来源、证据次数、建议结果和影响。
- 只有用户点击启用后，规则才参与后续排序与标记。
- 规则可暂停、重新启用、撤销或全部清空。
- 成功移到废纸篓可以增加提案证据，但不能自动启用规则。
- 学习系统不得修改程序代码、扩大权限、勾选项目、结束进程或执行删除。

### 4. 视觉 2.0

- 围绕“扫描状态 → 证据 → 决策 → 下一步”建立统一的信息层级。
- 使用原生材质和克制的半透明深度；材质用于表达层级，不作为每个区域的装饰。
- 总览突出单一主任务，磁盘页采用可选择的决策工作台，本机学习页突出待审核规则。
- 支持键盘焦点、减少动态效果和 VoiceOver 标签。
- 在 1280 × 800 及应用允许的最窄窗口下，不出现关键操作裁切。

## P1 范围

### 本机模型工作台

- 始终使用 oMLX `/v1/models` 返回的短 ID 作为请求 ID；文件路径只用于 App 自己启动模型。
- 展示健康检查耗时、服务模型列表和当前实际请求 ID。
- 提供用户主动触发的最小推理测速，显示首字延迟、总耗时和可用时的输出 token 数。
- 展示模型权重与本机物理内存的保守提示；不承诺实际吞吐，不自动下载或启动陌生模型。

### 系统诊断

- 电池状态必须区分“检测到电池”“这台 Mac 没有内置电池”“读取失败”，不能把前两者都写成权限不足或状态未知。
- 内存页继续解释压力、缓存、压缩、交换空间和进程近似足迹；结束进程前复核 PID 身份并提示未保存数据风险。

### 数据控制

- 活动记录支持用户主动导出和清空。
- 设置支持恢复安全默认值；不清除扫描结果、活动、本机学习或系统授权，除非用户在对应位置单独确认。

## 明确不做

- 不自动清理整个 `Library`、`Containers`、云盘或用户文档。
- 不允许模型选择目标、扩大扫描范围、删除文件或结束进程。
- 不读取文件正文，不连接公网模型，不公开本机模型服务。
- 不自动下载几十 GB 模型，不替用户接受第三方条款。
- 不自修改可执行代码，不把“成功一次”直接变成永久自动化。
- 没有 Developer ID 与公证时，不把源码构建描述为 Apple 可信安装包。

## 发布门槛

- `CFBundleShortVersionString`、Build、MCP 版本、SBOM、README、CHANGELOG 和 Git tag 一致。
- Swift 单元测试、`CleanNestSelfTest`、脚本语法、Apple Silicon 与 Intel CI、CodeQL 和依赖审查全部通过。
- 覆盖缓存命中/失效/绕过、部分结果、取消、旧索引迁移、AI 短 ID、模型超时/无效响应、权限阻断、符号链接、PID 复用和电池三态。
- 使用演示数据验证总览、磁盘、清理、本机学习、设置和活动记录；保存无隐私截图。
- 至少一次真实大目录的只读扫描验证，并记录环境、首结果、完整耗时、缓存耗时和取消行为；该证据不得进入包含用户名或私有文件名的公开截图。
- Developer ID、公证与装订属于独立发布通道；缺少资格不阻断源码版本，但必须在 Release 中明确标注信任边界。

## 发布顺序

1. 合并完整 0.5.0 实现的 Draft PR。
2. 主分支 CI 与安全检查通过后再生成候选产物。
3. 由维护者明确授权后创建正式 Release；不得用 Draft、预发布或 Actions 临时产物冒充最新正式版本。
