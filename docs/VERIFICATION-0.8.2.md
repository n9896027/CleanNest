## 结论

0.8.2 不改任何清理逻辑与安全边界，只改信息呈现：处置状态改说大白话，侧栏从 11 个常驻入口收敛为 6 个。全量测试 193 项通过（与 0.8.1 相同，无逻辑变更），GUI 构建通过，本机已替换并截图验证。

## 版本说明（用户可见变化）

**术语双层化**（Agent 工作区 / 清理 / 卸载三页优先）：

| 原技术术语（现降级为悬浮说明） | 大白话主文案 |
| --- | --- |
| 正在使用·已保护 | 在用·先别动 |
| 默认保留 | 建议保留 |
| 可归档复核 | 看一眼再定 |
| 可再生复核 | 可安全清理 |
| 只读查看 | 仅查看 |

连带替换：占用账本→占用/分类占用、工作痕迹→内容、进入预览→可清理、没有可执行动作→暂无可清理项、会话归档建议→旧内容建议、检查计划→查看清理计划、类别行的预览字节改为"可安全清理 / 需要先过目"两档。

**侧栏收敛**：总览 + 空间（清理空间/应用卸载/磁盘浏览）+ 活动记录 + 设置 共 6 个常驻入口；系统状态、系统维护、Agent 工作区、本地模型、本机学习收进"高级工具"分组，默认折叠，选中组内页面时自动展开，展开状态经 `sidebar.workshopExpanded` 本地记忆。

## 优化思路

依据 2026-08-29 的交互评估：App 的安全设计（备份优先、失败关闭、证据化）是资产，但术语体系把内部分类学直接暴露给了用户。原则改为：默认层只回答"能不能动、动了能不能恢复"，技术口径一律下沉一层（悬浮/折叠）。分层不改逻辑，因此零风险。
