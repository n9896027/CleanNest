# CleanNest 0.6.4 本机验证报告

日期：2026-08-27  
版本：0.6.4（Build 25）  
环境：当前 Apple Silicon Mac、macOS、本地稳定代码签名身份

## 结论

0.6.4 P2 已把 Agent 工作区扩展为一张以本机证据为准的运行关系图。Codex、Claude、Pi Agent、Kimi、WorkBuddy、Hermes、OpenClaw、Trae 与 MiniMax Hub 均有有界只读适配；没有可靠本机样本的小云雀明确显示为“待验证”，不会猜测目录。界面会分别呈现 App、数据目录、进程、launchd、监听端口与本地模型，并且只有 Agent 进程与模型监听端口之间存在已建立 TCP 连接时，才标记“模型实连”。已安装 Agent 的图标在运行时直接取自其本机 App Bundle；纯 CLI 或没有安装证据时使用中性回退，不在 CleanNest 中重新分发第三方素材。

新适配器不会获得文件处置权限。备份优先的恢复链仍硬编码限制在 Codex 与 Claude 的静置缓存、临时文件和日志；会话、索引、记忆、凭据、运行时、未知数据及其余 Agent 均保持只读。

## 关系图证据规则

1. App 节点来自已知 bundle ID 或应用名称，并保留是否实际安装的状态。
2. 数据节点只来自通过严格相对路径校验的有界根目录；父目录遍历、符号链接和过宽根目录会失败关闭。
3. 进程节点要求匹配精确 App bundle 路径或受限的可执行文件名，不使用泛化命令行关键词猜测。
4. launchd 节点来自当前用户域的只读枚举，只展示与 Agent 规则匹配的 job。
5. 端口节点来自实际监听证据；Agent 到本地模型的边还必须存在该 Agent PID 的 `ESTABLISHED` TCP 对端端口证据。
6. “安装了 Agent”和“本地模型正在运行”不会自动形成关系；证据不足时界面明确显示未验证。

## 签名规则边界

- 外部规则包必须是非符号链接目录、大小受限、结构合法，并通过 macOS 严格代码签名校验。
- 规则包叶证书必须与当前 CleanNest App 的叶证书一致；复制到 Application Support 后会再次校验。
- 规则只能扩展只读识别信息，不能把新 Agent 升级为可清理对象；处置权限由程序内硬编码边界决定。
- 导入失败、安装后复核失败或规则内容越界时自动回到内置基线，不会继续使用部分成功的规则。

## 尚未证明

- 当前机器没有小云雀的可复现样本，因此 0.6.4 没有为它猜测目录或进程标记。
- 本轮真机上没有 Agent 到本地模型的已建立 TCP 连接；真实负向结果已验证，正向连边由精确 TCP 夹具单元测试覆盖，但尚无本机正向运行样本。
- 没有对 Pi Agent、Kimi、WorkBuddy、Hermes、OpenClaw、Trae、MiniMax Hub 或小云雀的任何真实文件执行修改；这些适配器是只读的。
- 本报告不是 48 小时常驻、反复睡眠/唤醒或超大目录压力测试；约 188.2 MiB 是一次最终构建的时间点采样，不等同于长期内存上限。
- 本地稳定签名不是 Developer ID；当前构建仍不是 Apple 公证的公开安装包。
- 当前只有本机测试和构建证据；在对应提交推送并由 GitHub runner 执行前，不把 CI / CodeQL 冒充为已通过。
