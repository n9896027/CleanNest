# CleanNest 0.7.8 本机验证报告

日期：2026-08-27
版本：0.7.8（Build 35）
分支：`agent/0.7-series`

## 结论

0.7.8 已把 Agent 工作区从“一页展示所有账本、关系、候选和工具”改成任务分层：概览只显示总占用、变化、活跃保护和异常；进入单个 Agent 后才按供应方重新扫描并生成文件级处置证据。学习页不再同步渲染每条文件提案，而是按类型、位置级别、风险、时间和建议方向组成规则簇。

这是本机开发里程碑，不是 GitHub 正式 Release。当前构建使用稳定本地签名，不具备 Developer ID 与 Apple 公证信任链；真实 48 小时常驻仍属于 0.7.9 发布候选门。

## 已完成的用户结果

- Agent 首页只保留总量、相对上次变化、活跃保护和异常线索；每个 Agent 卡片是明确按钮。
- 概览 XPC 扫描显式关闭文件级执行令牌；点击 Codex/Claude 后才只扫描该供应方并生成允许类别的令牌。
- 单 Agent 详情按类别账本、安全处置/恢复、运行关系分层；恢复记录只显示所选供应方。
- 开发工具原生接口移到独立“工具账本”，不再占据 Agent 默认首页。
- 学习提案按“类型 + 位置级别 + 风险 + 时间 + 建议方向”聚类，支持整组审核、7 天试用、暂停、撤销和过期清理。
- 试用规则到期后自动暂停；过期记录只有用户点击后才删除。
- 学习页用当前扫描结果计算实际命中、移动、前移复核和后移保留数量，并明确显示规则自动改变的选择数为 0。
- 会话、凭据、索引、记忆和没有硬编码恢复能力的 Agent 仍无执行令牌；外部规则不能扩大该边界。

## 自动验证

- `swift test`：171 项通过，0 失败，1 项 Ollama 真机集成按设计需要显式环境变量而跳过。
- `CleanNestSelfTest`：全部检查通过。
- Release 构建：主 App、登录项和独立扫描服务均为 0.7.8（Build 35），深度严格签名验证通过。
- 本机构建签名：`Yuan OS Local Code Signing`；不是 Developer ID，因此没有把它描述成可供陌生用户直接安装的公证包。
- 构建后从 `build/CleanNest.app` 实际启动成功；启动约 3 秒时常驻集约 190 MB、CPU 约 2.8%，仅作为一次启动快照，不冒充长期内存结论。
- 新增边界覆盖：
  - 概览扫描有聚合占用但没有任何文件级令牌；
  - 单 Agent 扫描只返回所选供应方，令牌不能串到其他 Agent；
  - Pi Agent 即使作为详情请求也保持只读；
  - 单 Agent 详情合并后，其他 Agent 仍不携带令牌；
  - 10,000 条同类文件提案只投影为 1 个规则簇和最多 3 个示例名称；
  - 规则试用、到期自动暂停、批量状态和当前列表排序影响均有单元测试。

## 未冒充完成的事项

- 没有发现供应方提供稳定、可验证的会话归档/索引事务 API，因此会话归档继续只读。
- 没有用真实个人 Agent 文件执行处置；恢复事务沿用既有临时目录与身份重验测试。
- 没有把 10,000 条投影测试冒充 10,000 个 SwiftUI 行实机滚动测试；实现只向 UI 提供规则簇，文件 ID 数组留在核心内存用于批量状态变更。
- 没有完成 48 小时常驻、全语言 VoiceOver、Developer ID、公证或公开发布。
