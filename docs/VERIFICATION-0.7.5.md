# CleanNest 0.7.5 本机验证报告

日期：2026-08-27
版本：0.7.5（Build 32）
范围：系统状态、统一告警、紧凑菜单栏、内存进程汇总和高频刷新隔离

## 结论

0.7.5 的本机源码里程碑通过。菜单栏、弹出面板和系统状态页不再各自猜测异常；它们读取同一份可保存阈值和同一语义色。异常会进入只存本机的时间线，内存进程先按 App 聚合，菜单栏在空间不足时保留异常而收起普通项，不截断数值。

本轮还从正在运行的 0.7.4 捕获到一个真实性能缺陷：进程持续接近一个 CPU 核心满载，采样栈集中在 SwiftUI `LazyVStack` 布局。原因是 2 秒原生样本通过整个 `AppStore` 发布，并伴随重复诊断文字，导致当前磁盘长页持续重排。0.7.5 已把高频样本隔离为专用数据流，并对重复诊断做相等值抑制。

## 自动化证据

- `NativeSystemMonitorTests`
  - 保持 CPU/GPU/网络繁忙不等于故障。
  - 验证默认及自定义温度、磁盘余量、低电量与风扇相对负载阈值。
  - 验证只有 RPM、没有相对最大转速时不触发通用风扇告警。
- `SystemStatusPolicyTests`
  - 验证菜单栏预算始终保留异常项和首选项，且至少保留一个入口。
  - 验证告警的开启、升级、峰值、恢复、睡眠空档分段和本机持久化。
  - 以 2 秒间隔模拟完整 48 小时，共 86,400 个样本，验证事件上限与状态机稳定性。
  - 验证同一 App 的主进程与辅助进程聚合，仍保留逐进程身份。
- Agent 恢复回归
  - macOS 26 不支持普通 macOS 目录上的 iOS `completeFileProtection` 写入标志；现改为 `0700` 恢复目录、原子替换和 `0600` 清单，并增加权限断言。

## 真机证据与性能基线

- 0.7.4（Build 31）现场：PID 53032 在非扫描状态持续约 99% CPU；3 秒 `sample` 的 1,693/1,701 个主线程样本落在 SwiftUI 事务与懒布局重排路径。该现场只用于定位，没有据此猜测用户文件状态。
- 0.7.5（Build 32）修复后现场：新签名 App 的 PID 57185 连续 4 次、每次间隔 2 秒的非扫描采样均为 0.0% CPU；RSS 从 170,912 KB 变为 170,656 KB，没有出现随系统指标刷新持续增长的迹象。这是短程现场证据，不代替真实 48 小时常驻测试。
- `scripts/verify-system-monitor-soak.sh` 可按固定间隔记录 PID、RSS、CPU、告警文件更新时间、登录项和显示器数量。默认时长为真实 172,800 秒；开发快速检查可显式缩短。
- 当前只完成短程脚本自检和加速 48 小时状态机；尚未等待真实 48 小时，也没有在本轮人为制造多次睡眠/唤醒或外接屏幕切换。

## 用户可见结果

- 设置可展开“异常阈值”，并恢复保守预设。
- 实时仪表和弹出面板在变色时直接说明哪一数值达到哪条线。
- 告警时间线显示持续中/已恢复、峰值、起点和持续时间；不记录网络地址或流量内容。
- 内存列表按 App 显示汇总体积，展开后才出现具体进程和逐项退出确认。
- 菜单栏完整测量文字宽度；窄屏时自动收起普通项目，异常项不会因预算被丢弃。
