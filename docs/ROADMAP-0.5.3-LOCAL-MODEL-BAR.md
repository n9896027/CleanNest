# CleanNest 0.5.3 计划：本地模型运行中心

> 实施状态（2026-08-24）：核心发现、独立功能栏、MODEL 菜单栏状态、结构化启动、外部进程精确终止，以及用户 launchd 守护的发现、风险确认、停用和恢复链已实现。当前本机已实际确认 oMLX 由 `homebrew.mxcl.omlx` 的 `KeepAlive` + `RunAtLoad` 自动拉起；关闭旧 PID 后出现新 PID 的原因已被证据化。守护最终停用按钮只验收到确认前，尚未为了开发验收再次中断用户服务。MLX-LM、LM Studio、llama.cpp、睡眠恢复与 48 小时耐久门槛仍待真实样本，不能视为已通过。

## 产品结论

0.5.3 新增一个独立的“本地模型”功能栏，解决三个直接问题：

1. 这台 Mac 现在是否有模型服务在运行？
2. 运行的是什么模型、什么平台、监听在什么地址？
3. 能否在明确边界内一键启动或停止？

这不是把终端嵌进 App，而是对本地模型运行时做可解释、可恢复、有所有权边界的图形化管理。

## 首批支持平台

| 平台 | 发现方式 | 模型识别 | 启停策略 |
| --- | --- | --- | --- |
| oMLX | 本机端口、进程与 `/v1/models` | 使用 oMLX 返回的短 `id` | 自有实例直接停止；外部实例风险确认后精确停止 |
| MLX-LM Server | 进程与 OpenAI 兼容接口 | 模型目录别名与服务 `id` 分开展示 | 使用经校验的启动配置 |
| Ollama | 本机进程与 `/api/tags` | Ollama 模型名称 | 优先使用官方命令边界 |
| LM Studio | 本机监听端口与 `/v1/models` | 服务实际返回的 `id` | 风险确认后正常退出；强制结束需二次确认 |
| llama.cpp | 进程、监听端口与健康接口 | 启动配置与 API 结果交叉验证 | 自有实例直接停止；外部实例风险确认后精确停止 |

0.5.3 不默认扫描整个局域网，也不猜测远程主机。它只检查本机监听进程、回环地址、本机内网地址，以及用户明确添加的端点。

## 信息层级

菜单栏只显示最小状态：

- 绿色：已运行且健康；
- 橙色：进程存在，但 API 尚未就绪或模型身份未确认；
- 灰色：未运行；
- 红色：启动失败、端口冲突或配置错误。

点开后展示：

- 平台与可执行文件来源；
- 服务返回的模型短 `id`；
- PID、启动时间、运行状态与 CleanNest 是否拥有该进程；
- 回环地址（例如 `127.0.0.1:8080`）和可用的内网地址；
- 暴露级别：“仅本机”、“局域网可访问”或“地址未确认”；
- 内存估算、实际进程占用与最近错误。

## 运行状态机

```text
unknown -> discovering -> stopped
                      -> runningUnverified -> runningHealthy
stopped -> startPending -> runningUnverified | failed
runningHealthy -> stopPending -> stopped | failed
```

每个结果必须带证据来源：进程、launchd 守护、监听端口、平台 API、用户配置或 CleanNest 自己的进程记录。“看到 PID”不等于“模型可用”，而“PID 退出”也不等于守护服务已停用。

## 一键启停的安全边界

- 只有 CleanNest 启动并持有身份记录的进程，才能无需额外风险表直接“停止”。
- 对外部启动的进程，只有取得 PID 以及启动时间或可执行文件等足够身份时才显示“关闭外部服务…”；先列出客户端断开、未保存状态、局域网访问、主 App 退出和自动重启等适用风险。
- 用户确认后强制重新发现目标，并把原快照、刷新快照与即时进程快照的 PID、启动时间、当前用户和可执行文件交叉复核。身份不一致、系统/关键进程或其他用户进程一律拒绝。
- 先向精确目标发送 SIGTERM；3 秒仍存活时才显示强制选项，且必须再次勾选风险确认才可发送 SIGKILL。不使用模糊进程名称批量结束。
- 若 PID 对应当前用户标准 LaunchAgent，显示精确标签、plist 来源、`KeepAlive` / `RunAtLoad` 与停用状态；“停用守护并关闭”必须再次勾选，并在执行前复核标签、gui 作用域、用户所有权和 plist 设备号/文件号。
- 守护停用只调用结构化 `launchctl disable` + `bootout`，不编辑或删除 plist；停用实例仍留在列表并提供经过同一身份复核的 `enable` + `bootstrap` 恢复入口。系统和其他用户守护只读。
- 启动配置以结构化参数保存，不拼接未校验的 shell 命令。
- 停止失败会保留当前状态与诊断，不假装已停止。

## oMLX 与 DFlash2 回归要求

- 调用 `/v1/chat/completions` 时，`model` 必须使用 `/v1/models` 返回的短 `id`，例如 `Qwen3.8-27B-Uncensored-8bit`。
- 不得把模型文件路径当作服务 `id`；该回归用例必须防止 404 与无限转圈。
- DFlash2 只作为当前运行配置展示；不在未验证平台支持时自动切换。
- 连接测试必须区分“端口可达”、“模型列表可读”和“最小推理成功”三个阶段。

## 隐私与网络

- 不发送提示词来发现模型；“最小推理测试”必须由用户主动点击。
- 不记录或上传内网地址、模型名、提示词或进程参数。
- 不展示可能包含密钥的完整环境变量或命令行。
- 监听在 `0.0.0.0` 或局域网地址时显示明确暴露警告，但不擅自修改防火墙。

## 实施里程碑

1. **只读发现层**：建立平台适配器、本机监听证据和状态机。
2. **功能栏与详情面板**：完成菜单栏状态、平台/模型/地址展示和暴露警告。
3. **可控启动配置**：先支持 oMLX 与 MLX-LM，然后扩展到 Ollama 与 llama.cpp。
4. **身份安全停止**：自有进程按所有权直接正常退出；外部进程完成风险表、三段身份复核、SIGTERM 优先、二次确认 SIGKILL 与失败恢复。
5. **守护证据与恢复**：关联 launchd 标签、自动重启策略与 plist 文件身份；只对精确用户 LaunchAgent 提供确认停用和重新启用。
6. **回归与耐久验收**：覆盖端口冲突、外部进程、错误模型 `id`、启动后崩溃、守护自动拉起、休眠恢复和登录启动。

## 发布验收门槛

- 在 oMLX、MLX-LM、Ollama、LM Studio 和 llama.cpp 中，至少完成两种平台的真实运行验证，其他平台明确标为只读预览或实验性。
- `Qwen3.8-27B-Uncensored-8bit` 短 `id` 用例通过，文件路径误作 `id` 时必须立即显示可操作错误。
- 外部进程不得绕过风险表或身份复核；不得一键强制结束，SIGKILL 只能在 SIGTERM 超时并完成二次勾选后使用。
- 守护停用不得按名称猜测或批量匹配；系统/其他用户服务不得提供可执行入口，plist 不得删除，恢复必须再次核对同一文件身份。
- 局域网暴露状态与实际监听地址一致。
- 启动、停止、崩溃、休眠/唤醒和 App 重启后的状态都不假成功。
- 完成至少 48 小时本机后台耐久测试；在时间未实际跑满前，不宣称该门槛已通过。

## 本版不做

- 不下载或自动删除模型权重；
- 不扫描整个局域网；
- 不接管云端 API 密钥；
- 不对模型“好不好”做无证据评分；
- 不为了方便而批量结束同名进程。
