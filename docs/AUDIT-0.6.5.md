# CleanNest 0.6.5 全栏目审计

日期：2026-08-27  
范围：主窗口 11 个导航栏目、菜单栏监测、更新入口、启动任务与主要安全边界  
方法：当前分支源码审计 + 本机最终 0.6.4 功能构建的只读逐页巡检 + 进程内存摘要。0.6.5 只封存这一功能集并同步版本号，不在审计时触发清理、卸载、结束进程、停用模型或修改权限。

## 结论

0.6.5 适合作为 **0.6 系列的本地源码封存版**：核心栏目已有真实任务和失败关闭边界，不再是只有卡片和按钮的演示壳。但它不适合被宣传为“已完全成熟的普通用户安装版”，主要原因不是缺少更多功能，而是当前架构、内存、信息分层、无障碍与可信分发尚未达到同样的深度。

封存不包含 Git 提交、tag、GitHub Release、Developer ID 签名或 Apple 公证。这些必须在分支通过完整本机与远端检查、合并到受保护的 `main` 后分别完成。

## 架构与性能证据

### P0：启动工作超出用户当前任务

`AppStore.bootstrap()` 在每次启动时同时准备模型目录、历史指标、文件权限、Mole 状态、本地模型发现和整个 Agent 工作区。Agent 文件遍历虽已放在 XPC 内，但完整快照仍会在主 App 内持有。用户只想看菜单栏 CPU 时，不应默认支付全 Agent 账本的启动成本。

### P0：单一全局状态容器已成为发布瓶颈

- `Sources/CleanNest/AppStore.swift`：4,552 行，121 个 `@Published` 属性。
- `AgentWorkspaceView.swift`：1,767 行；`SettingsView.swift`：1,390 行；`DiskAnalyzeView.swift`：1,206 行；`MenuBarMonitor.swift`：981 行。
- 高频指标、文件扫描、模型发现、活动记录与页面导航共享同一发布面，容易让不相关页面重算。
- 多个长列表仍使用普通 `VStack` + `ForEach`，页面离开后的图层和视图状态回落不够可控。

### P0：实测内存仍有明显峰值和回落问题

在当前 Mac 上完成逐页只读巡检后：

- `ps` 的 RSS 时间点读数约 649 MiB。
- `vmmap -summary` 的 physical footprint 约 440 MiB，本次进程峰值约 1.5 GiB。
- CoreAnimation 驻留约 167 MiB；Malloc 脏页合计约 180 MiB。

这是可复现的时间点证据，不足以单独证明某一处内存泄漏，但已足以否决“内存问题已完全解决”的结论。0.7.0 需要用自动化页面巡游、扫描前后标记和稳定后预算证明改进，不能只凭一次冷启动 RSS。

### P0：本机学习存在无障碍缺口

本轮使用 macOS 辅助功能树读取其他栏目时，可识别标题、按钮、状态、读数和列表。“本机学习”页只暴露了空的滚动容器，页内规则和操作没有可用的语义树。这不能用“视觉上能看到”替代，应在 0.7.0 就建立页级无障碍回归门，并在 0.7.8 完成该页重构。

## 封存边界

0.6.5 保留以下硬边界：

- 所有文件处置默认可恢复，不执行永久删除。
- AI 只读取受限、脱敏元数据，不产生路径、勾选或执行权限。
- 外部模型服务和进程操作在执行前重新复核精确身份；系统/其他用户守护只读。
- Agent 会话、私有索引、记忆、凭据和未验证适配器只读。
- 完全磁盘访问只能依据真实读取结果判断，不得把打开系统设置当成授权成功。
- 没有 Developer ID 和公证证据时，只能声称源码可构建或本地稳定签名，不声称官方可信安装包。

## 0.7 系列的统一验收门

从 0.7.0 开始，每个小版本除了功能验收，还必须同时通过：

1. 单元测试、`CleanNestSelfTest`、Release 构建、嵌套签名与 `git diff --check`。
2. 本轮触及页面的辅助功能树和键盘路径。
3. 一条正常流、一条取消/拒绝流、一条身份变化的失败关闭流。
4. 对应的启动、任务峰值和页面离开后内存回落证据。
5. 中英文案和窄窗口布局；不允许关键数值用省略号代替。
6. 清理、卸载、进程、模型守护和维护任务的活动证据及恢复边界。
