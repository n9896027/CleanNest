# 本机历史指标

CleanNest 同时提供短期实时采样和长期历史。实时菜单栏可选每 1、2、5 或 10 秒原生采样，不依赖 Mole，只在内存中保留最近 90 个点；App 运行且 Mole 已连接时，另外每 60 秒将系统状态写入长期数据库。趋势用于回答“内存或 CPU 是刚刚升高，还是持续异常”，不用于硬件故障诊断。

短期原生样本包含 CPU 总量与用户/系统/空闲分解、内存、启动卷容量与磁盘读写速率、网络收发、GPU 总量与 Renderer/Tiler、CPU 与电池温度、逐风扇转速和电池状态。网络默认合计物理网卡，不把 VPN 隧道与物理流量重复累加。

实时链路读取 CPU、内存、主网络接口、启动卷、GPU、AppleSMC CPU 核心温度、IOKit 电池温度以及只读风扇计数。两种温度在同一张实时卡中按传感器分别标注，不把电池温度冒充 CPU 温度。网络只保留速率差值，不保存 IP、域名、连接对端或流量内容。硬件没有提供有效计数时，字段保持缺失，不以 0 代替。

## 记录内容

- CPU 占用、内存占用与内存压力
- 已用、可用、压缩内存与交换空间
- 磁盘占用和可用空间
- 原生电源接口与 Mole 能提供时的电池电量、温度、健康分数和进程数。电池可用性单独区分“存在”“没有内置电池”和“读取失败”；没有内置电池不是权限错误。

不记录进程命令行、文件内容、目录树、账号、网络地址或用户输入。单次采样缺失的字段以空值保存，不伪造为零。

## 存储与保留

数据库位于 `~/Library/Application Support/CleanNest/metrics.sqlite3`，使用 SQLite WAL。默认保留 30 天，可在设置中改为 7、30、90 或 365 天，也可立即清空。App 启动和每次写入后都会按保留期限修剪旧样本。

图表支持 1 小时、24 小时、7 天和 30 天窗口。查询有数据点上限，避免长时间运行后一次加载过多样本。

## 并发与失败边界

GUI 是唯一写入者。内置 MCP 只以 SQLite 只读模式打开数据库；数据库尚不存在时，MCP 不会创建它。SQLite WAL 允许 GUI 继续采样时，本机 MCP 客户端读取一致的历史快照。

历史写入失败不会阻止当前状态页刷新，也不会触发文件清理或进程操作。设置页会显示具体的本机诊断状态。
