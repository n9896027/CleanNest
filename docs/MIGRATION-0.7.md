# 0.6.5 → 0.7.x 数据升级与回退

CleanNest 的升级原则是：用户文件不参与迁移，只有 CleanNest 自己的偏好、指标、活动、扫描索引、学习规则和恢复记录会被读取。不能可靠降级的状态必须失败关闭，不能把旧程序不理解的规则偷偷当成永久规则。

## 兼容矩阵

| 状态 | 0.7.x 升级行为 | 回到 0.6.5 时的行为 |
|---|---|---|
| 设置 / 菜单栏偏好 | 缺少的新字段采用保守默认值；保留已有指标开关和顺序 | 0.6.5 忽略它不认识的新字段，仍能读取原字段 |
| 指标数据库 | SQLite schema 仍为 1，沿用原表和 WAL | 可继续读取；没有不可逆迁移 |
| 活动记录 | 旧记录没有“候选/废纸篓/APFS”明细时保持为空，不伪造结果 | 新明细字段会被旧解码器忽略；原有标题、结果、项目数和体积保留 |
| 磁盘扫描索引 | schema 1 原位升级到 2，新增遍历证据为空；未来未知 schema 只丢弃缓存 | 0.6.5 会把 schema 2 当成失效缓存并重扫；不会触碰用户文件 |
| 学习规则 | schema 1/2 升级到 3；新增位置、风险、时间和试用到期信息 | 0.6.5 不理解 schema 3，会失败关闭并暂时不应用学习排序 |
| Agent 观察记录 | 数据结构保持兼容 | 可以继续读取 |
| Agent 恢复记录 | 0.6.5 字段和 ISO-8601 日期保持不变 | 可以继续读取与恢复；恢复前仍重验文件身份和压缩包校验 |

## 学习规则回退备份

第一次把旧学习文件保存为 schema 3 前，CleanNest 会在同一目录保留一次性副本：

`evolution-memory.pre-v3.json`

副本只在原文件确实是 schema 1 或 2、且备份尚不存在时创建；后续保存不会覆盖它。它和原学习文件一样只包含哈希身份、类别、选择和评价，不包含文件正文或完整路径。

若必须回到 0.6.5：

1. 先完全退出 CleanNest，避免新旧版本同时写入。
2. 保留当前 `evolution-memory.json` 作为回退前副本。
3. 把 `evolution-memory.pre-v3.json` 复制为 `evolution-memory.json`。
4. 启动 0.6.5，确认学习规则数量和设置；不要删除 Agent 恢复目录。

CleanNest 不会在降级时自动覆盖当前规则，因为旧版程序无法理解 7 天试用的到期语义；自动转换可能把试用规则误变成永久规则。

## 自动验证

`MigrationCompatibilityTests` 使用 0.6.5 的字段形状覆盖设置、活动、磁盘索引、学习规则、Agent 观察与恢复记录，并验证：

- 旧数据升级后保留可证明的值；
- 新增字段缺失时采用空值或安全默认值；
- 新数据退回旧字段形状时，未知字段不会破坏原字段；
- 学习 schema 3 对 0.6.5 明确失败关闭，同时保留可读的 schema 2 备份；
- 低磁盘空间在创建 Agent 备份和移动原文件之前就被拒绝。
