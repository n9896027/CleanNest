## 本轮范围

- 磁盘浏览中的系统数据占用清单：25 个固定、互不嵌套的当前用户目录；大小、来源、用途、处理后果、搜索、过滤、扫描缺口、在 Finder 查看和已有管理页跳转。
- 扫描按需在独立 XPC 服务执行，每处最多 100,000 个遍历项，沿用物理 POSIX 遍历；不读取文件正文，不运行工具清理命令，不新增网络请求。
- 未授权保护目录在 stat 前跳过；中间路径及根路径的符号链接、跨卷位置跳过；不可读与未找到各自标记，不伪造 0 字节。
- 状态只保留两次紧凑报告在内存中；同位置、同口径、两次完整测量才展示变化。退出即清空；无新的长期记录文件。
- 旧 PR #14 的每页 40 项清理结果分页修复及回归测试已纳入，不改变选择与删除策略。
- npm / pip 磁盘明细与新清单复用下载来源和重新下载影响说明，修正旧的编译 / 模拟器笼统描述；清理边界及风险下限不变。

## 验收中发现的权限探测缺陷

旧实现只探测用户级 TCC 文件，本机该文件不存在；这不是“没有授权”的证据。
新增系统保护位置的只打开 / 立即关闭探测，并在 POSIX 调用返回时立即捕获 errno。
不读取 TCC 内容、不查询其表、不修改权限。任一成功访问才报告可访问；缺失及其他错误仍失败关闭。
[Apple DTS 的说明](https://developer.apple.com/forums/thread/835851)明确区分实际能访问什么与确认 FDA 开关；后续每项实际读取仍独立判断失败。

## 明确边界

- 这不是 Apple 私有“系统数据”分类的精确还原。没有扫描系统快照、swap、系统级模拟器运行时、其他用户或任意自定义模型目录；默认位置未找到不等于软件未安装。
- 计量为文件分配块；硬链接与 APFS 克隆可能共享块，不能把合计叫“可释放空间”。系统可回收估计不保证即时可用。
- 不新增删除 allow-list；“可重建”是用途分类，不是删除授权。由现有清理、模型或 Agent 页面进行下一步复核；Docker、模拟器、设备备份仍由所属工具管理。
- 非原子全盘快照；扫描期间文件可能变化。只读预检不构成任何后续删除许可。
- 新说明以中文为主；完整多语言 UI、VoiceOver、Intel 实机、48 小时常驻、Developer ID 与 Apple 公证未在本轮验证。
- macos-sysdata 的最新版采用专有许可。本次仅研究功能说明并独立实现，未复制其代码或素材，未安装该 App。
