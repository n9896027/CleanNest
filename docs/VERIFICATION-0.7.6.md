# CleanNest 0.7.6 本机验证报告

日期：2026-08-27
版本：0.7.6（Build 33）
范围：系统维护只读诊断、影响确认、执行后复核与本机证据历史

## 结论

0.7.6 将原来的四个“直接运行”按钮改成诊断闭环。用户先看到基础检查能证明什么、不能证明什么，再决定是否执行；执行后以新的只读证据判断服务是否返回。命令成功与问题恢复是两个状态，无法确认时不会写成成功。

## 自动化证据

- Xcode 工具链全量执行 155 项测试，0 失败。
- 每个维护动作都覆盖基础检查未发现异常、发现异常、执行并验证恢复、执行后仍未恢复四条路径。
- 额外覆盖预检不可用和命令失败；两者都不能产生成功结果。
- Finder、Dock、SystemUIServer 只有出现新的 PID 才判为服务恢复。
- Quick Look 只判定缓存命令完成且基础接口重新响应，不判断某个用户文件的预览内容。
- 维护历史经过 ISO 8601 JSON 往返验证，并限制为最近 40 条。

## 本机只读检查

- 当前用户的 Finder、Dock 与 SystemUIServer 均可通过精确进程名读取到 PID。
- `/usr/bin/qlmanage -m` 返回 0，输出基础生成器/服务信息；该检查没有重建缓存或修改用户文件。
- Release App 已用稳定本机身份完成嵌套签名，App、登录项、扫描服务和只读 MCP 通过严格签名校验；启动后版本为 0.7.6（Build 33）。
- 本轮验证没有为了测试而重启 Finder、Dock 或菜单栏，也没有清理真实用户文件。

## 用户可见结果

- 未检查的任务显示“先诊断”，并说明该步骤不会重启服务。
- 诊断后显示状态、时间、直接证据和证据边界；基础正常时仍提醒反复运行不会让 Mac 更快。
- 执行确认窗同时展示诊断、症状、界面影响、安全边界和未恢复时的处理方法。
- 最近一次维护显示执行前、执行后与最终结论，可进入活动记录继续追溯。

## 安全边界

- 仍只有四项固定、无特权的系统界面维护动作。
- 不使用 `sudo`，不修改 SIP/TCC，不清空系统日志，不永久删除文件，不把重启服务描述为“提速”。
- 历史只保存维护动作、时间、证据状态和相关服务 PID，不保存窗口内容、用户点击或文件正文。

## 未冒充完成的门

- 本轮只对真实服务做只读预检，没有故意打断当前桌面会话来制造四个真机恢复案例；执行路径由确定性策略测试和既有固定命令约束覆盖。
- 本机稳定签名不是 Developer ID，当前构建没有 Apple 公证。
- 本报告不代表 GitHub PR、合并、tag 或公开 Release 已完成。
