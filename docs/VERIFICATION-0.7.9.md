# CleanNest 0.7.9 本机候选验证报告

日期：2026-08-27
版本：0.7.9（Build 36）
分支：`agent/0.7-series`

## 结论

0.7.9 已完成本机发布候选的工程硬化：0.6.5 数据升级/回退、取消风暴、模型服务上下线、低磁盘保护、三语言缺口审计、48 小时报告校验器，以及与提交绑定的 SBOM、SHA-256 和来源清单生成链。

它还不是通过所有门的对外正式版：真实 48 小时尚未经过，English/繁體中文仍有可见的简体中文回落，本机只有 `Yuan OS Local Code Signing`，没有 Developer ID Application 和 Apple 公证。因此本轮不创建公开 tag、不上传未公证 App，不让应用内更新检查把候选产物当成正式版。

## 自动验证

- `swift test`：179 项，0 失败；1 项需要显式开启真实 Ollama 环境，按设计跳过。
- `CleanNestSelfTest`：全部检查通过。
- Release 构建：主 App、登录项和独立扫描服务均为 0.7.9（Build 36）；`codesign --verify --deep --strict` 通过。
- 数据兼容：6 组测试覆盖设置、活动、磁盘索引、学习规则、Agent 观察/恢复记录和指标库。旧学习文件升级前保留一次性 `pre-v3` 副本，未来未知 schema 失败关闭。
- 取消回归：24 轮连续扫描取消都没有发布“已完成”假进度。
- 模型回归：服务出现、消失的连续序列只生成对应事件，不虚构替换模型。
- 低磁盘回归：Agent 备份所需逻辑体积加 512 MiB 安全余量；空间不足时在创建备份或移动原文件前拒绝。
- 48 小时报告校验器通过 120 秒加速样本，能拒绝时长不足、进程中断、无效 RSS/CPU 和超限峰值。这只验证报告器，不冒充真实 48 小时。

## 三语言与界面证据

- String Catalog 有 795 个条目，简体中文、English、繁體中文各有 795 个非空值。
- 源码审计仍有 194 个直接显示的静态中文字符串未进入 Catalog，另有 73 个带插值的中文文案需要人工改成可验证的格式化本地化。
- 严格本地化门按设计以退出码 3 失败，因此没有宣称 English/繁體中文已完整覆盖。
- 以 900×700 对总览、清理、磁盘、系统状态、模型、Agent、本机学习和设置做了三语言 24 张截图。简体中文关键信息没有被省略；English 和繁體中文截图直接暴露了局部简体中文回落，这是真实发布阻断，不隐藏。
- 截图收集器已修复默认语言列表未正确拆分的问题，并证实生成 3 种语言×8 个页面的独立图片。

## 磁盘口径说明

“已扫描/已归类 314 GB”是文件遍历可见项的分配块合计；“可用 126 GB”是 APFS 卷当前可用容量。快照、可清理空间、克隆块、其他 APFS 卷、系统保留与权限不可见内容会使两者出现巨大差异。界面已将“APFS 总账”和“文件已归类”分开，差额不会被冒充为可清理空间。
