# CleanNest 0.7.4 本机验证报告

日期：2026-08-27  
版本：0.7.4（Build 31）  
范围：APFS 容量总账、文件归类完整度、可靠增长对比和所属 App 入口

## 结论

0.7.4 的本机源码里程碑通过。磁盘浏览不再把文件遍历合计写成磁盘实际占用；界面同时显示 macOS/APFS 总账和 CleanNest 已归类文件，并把无法对账的差额、条目上限、读取失败、跨卷跳过与旧缓存完整度明确展示。

“差额”不等于垃圾，也不会生成任何清理候选。磁盘浏览继续只读。

## 当前 Mac 的问题复现与修复证据

旧索引中启动卷根报告只有四个顶层项目：`Library`、`System`、`Users`、`Applications`，分配块合计 **314,444,537,856 字节**。旧扫描器对每个顶层项目最多访问 500,000 项，却没有把触顶状态带回界面；根枚举还跳过隐藏项目。

同一台 Mac 的 APFS 容器总账在核验时显示：

- 总容量：994,662,584,320 字节（994.7 GB）
- 问题截图时的实际已用：约 868.6 GB
- 问题截图时的实际可用：约 126.1 GB
- 314.44 GB 与当时 APFS 已用之间的解释差额：约 554.16 GB

核验期间磁盘内容发生变化，APFS 可用空间后来变为约 137.0 GB；这也证明可用空间是实时卷状态，不能与旧扫描快照混为一个时间点。

0.7.4 合成界面使用问题发生时的数值，辅助功能树与截图均确认可读：

- `APFS 实际已用 868.6 GB`
- `APFS 实际可用 126.07 GB`
- `已归类文件 314.44 GB`
- `还有 554.16 GB 未被文件遍历解释`
- `达到条目上限`、`1 个目录触顶`、`7 项不可读`
- `深度重扫，不设条目上限`

## 完整度与增长门

- 普通扫描每个顶层项目保持 500,000 项上限；深度刷新不设该上限，两者都可取消并留在独立 XPC。
- 根枚举包含隐藏项目；递归遍历不跟随符号链接并停留在当前文件系统，不把外接卷或 DMG 重复计入启动卷。
- 缓存 schema v2 连同容量保存遍历完整度；旧缓存完整度未知时明确降级。
- 历史按根路径 SHA-256 身份隔离，每根只保留两份聚合快照。达到上限、存在不可读项目或旧缓存未知的扫描不能成为增长基线。
- 取消、XPC 中断、权限阻止或根变化时恢复上一次报告、根、卷总账、覆盖证据与比较基线的整套状态。
