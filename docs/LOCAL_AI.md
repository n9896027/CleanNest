# 可替换的本机 MLX 模型

本机 AI 是可选的解释层，不是扫描或删除引擎。关闭 AI 后，确定性扫描、磁盘浏览和安全规则仍能工作。

## 要求

- Apple Silicon Mac；`mlx-lm` 不用于 Intel Mac。
- 若复用 oMLX 等现有回环服务，只需服务能提供 `/health`、`/v1/models` 与 `/v1/chat/completions`；不要求再选择模型目录。
- 若由 CleanNest 自己启动服务，则需要一个已下载并转换为 MLX 格式的模型目录（至少含 `config.json` 和 `.safetensors` 权重），以及可执行的 `omlx` 或 `mlx_lm.server`。CleanNest 默认查找 `~/.mlx-env/bin/mlx_lm.server`，也可在设置中选择 Homebrew oMLX。
- 足够的统一内存。27B 级模型即使量化后也会占用大量内存；出现内存压力或交换空间持续增长时，应改用更小模型。

CleanNest 不自动下载或载入模型，也不替用户接受任何模型托管站点或模型发布者的条款。

## 连接方式

在“设置 → 本机 AI 分析”中：

- 服务地址：只允许 `http://127.0.0.1:<端口>/v1`；
- API 模型：读取 `/v1/models` 公布的模型 ID；可以保持“自动”使用服务默认模型，也可以明确选择某个 ID；
- 自启模型：App 会有界扫描 `~/Models/MLX`、`~/mlx-models`、`~/.omlx/models` 与 Hugging Face 本机缓存，列出完整模型；
- 模型目录：也可手动选择其他包含 `config.json` 与 `.safetensors` 权重的目录；
- 运行程序：选择 `omlx` 或 `mlx_lm.server`；其他程序可用于外部服务发现，但 0.5.3 不会直接启动。

“模型工作台”只在用户点击后向当前回环服务发送一个要求输出 `OK` 的最小流式请求，不携带扫描结果、文件名或路径。它显示健康检查延迟、首个可见输出时间、总耗时和服务实际接受的模型短名；这只是当前机器与当前负载的一次连通性/交互延迟实测，不代表长文本吞吐保证。

若模型目录可读，界面还会比较权重文件大小与本机物理内存。该提示不包含 KV 缓存、运行时、DFlash 草稿模型和其他 App 峰值，因此只能用于初筛，不能视为“必定可载入”的承诺。

选择器会显示模型架构、量化方式与权重大小。仅保存时不会自动载入大模型；选择“切换并启动”后，CleanNest 会先安全停止由 App 管理的旧模型，再启动新模型并记住选择。App 会优先探测已有回环服务并直接复用。设置页的 AI 开关只直接停止由 CleanNest 自己启动的服务；用户独立启动的服务必须到“本地模型”运行中心阅读风险并单独确认，避免一个设置开关意外打断其他客户端。

## 本地模型运行中心

侧边栏“本地模型”和菜单栏 `MODEL` 状态会按 10–60 秒自适应节奏交叉检查进程、TCP 监听/已建立连接、平台 API 和 launchd 守护。模型页最快，App 非活跃或没有运行实例时自动降频。oMLX、MLX-LM、Ollama、LM Studio 和 llama.cpp 由独立可测试适配器识别；未知但能返回 `/v1/models` 的本机服务会标为“OpenAI 兼容服务”并保持更保守的控制边界。

- 只有平台 API 返回可用短 ID 时才显示“健康”；仅有 PID 或端口时显示“待确认”。
- 运行拓扑按“平台 → 服务 → 模型短 ID → 客户端 → 守护”展示；客户端只来自已建立 TCP 连接，没有证据时显示“未观察到”。
- Ollama 使用 `/api/tags` 确认服务，并用 `/api/ps` 区分“服务在运行”和“模型已加载”。
- 监听在 `127.0.0.1` / `::1` 时显示“仅本机”；通配或非回环监听会显示局域网暴露警告。
- 内网地址只用于当前界面推导，不写入设置、活动记录或历史数据库。
- 完整命令行只在内存中用于识别平台，不进入 UI 或持久化；环境变量不会读取或展示。
- 守护发现只读取标准用户/本机 LaunchAgents 与 LaunchDaemons 的标签、程序、`KeepAlive`、`RunAtLoad` 和文件身份；plist 参数只在内存中用于平台分类，环境变量不读取。系统和其他用户守护保持只读。
- CleanNest 自己启动并持有身份的实例可直接正常停止。外部 oMLX、Ollama、LM Studio 或 llama.cpp 只有在能取得足够进程身份时才显示“关闭外部服务…”；点击后先展示客户端断开、未保存状态、局域网访问和自动重启等风险。
- 用户确认后，CleanNest 会重新发现目标，并以 PID、启动时间、当前用户和可执行文件复核是否仍是同一进程；只向该进程发送 SIGTERM。若 3 秒后仍在运行，界面才提供需再次勾选风险确认的 SIGKILL。身份不足、PID 已重用、系统/关键进程或其他用户进程保持只读并被拒绝。
- 若模型 PID 精确对应当前用户拥有的 LaunchAgent，界面会显示守护标签、配置路径及 `KeepAlive` / 登录启动状态。选择“停用守护并关闭”需再次勾选确认；执行前会复核 PID、标签、gui 作用域和 plist 设备号/文件号，再用结构化 `launchctl disable` + `bootout` 阻止自动拉起。plist 不删除，停用的服务仍会显示并可重新启用。
- 启动 CleanNest 已配置模型前会立即重新发现；端口被占用、模型目录不完整或自启程序不受支持时保持不可启动并显示原因。睡眠时不停止模型；唤醒后重新核对 PID、端口、短 ID、客户端和守护。

### oMLX 的模型短名

发给 OpenAI 兼容接口的 `model` 必须是 `/v1/models` 实际返回的 ID，例如 `Qwen3.8-27B-Uncensored-8bit`，不能把 `/Users/.../模型目录` 当作 API 模型 ID。CleanNest 将两者分开保存：短名用于请求，目录只用于 App 自己启动 `mlx_lm.server`。显式选择的短名若已不在服务列表中，App 会报错并要求重新选择，不会悄悄切换到另一模型。

oMLX 的 DFlash 是目标模型内部的推测解码加速设置；启用后，请求仍应使用目标模型的短名，而不是 DFlash 草稿模型路径或草稿模型 ID。CleanNest 只读取服务公开的 ID，不修改 oMLX 的 DFlash 设置。

## 会发送给模型什么

清理候选只包含受限 token、类型、大小、距今天数、扫描器建议、用途说明和脱敏路径提示。磁盘解释只包含当前层级及最多四个大目录的有限直接子项名称、类型和大小样本。

不会发送文件正文、凭据或完整目录树。用户主目录在请求中替换为 `~`；模型只看到 token，不能指定新路径。

## 结果如何受到约束

- 响应必须是大小受限、字段完全匹配的 JSON。
- 每个 token 必须恰好对应本次请求中的一个项目；额外路径和命令字段会被拒绝。
- `Containers`、云文档、用户内容等本机安全分类优先于模型判断。
- 模型越过风险边界时，客户端会降低置信度并采用更保守的本机结论。
- AI 不会自动勾选、删除、关闭进程或运行命令。

## 选择模型

优先考虑指令遵循稳定、能输出严格 JSON 且与你的统一内存匹配的 MLX 模型。大模型不一定让目录判断更可靠：CleanNest 故意不提供文件正文，最终结论仍受观测范围限制。27B/30B 级模型即使量化后也可能占用大量统一内存；资源紧张时，小型量化模型通常响应更快、更稳定。

项目只验证协议与安全边界，不保证某个第三方模型版本的输出质量。相关许可证见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。
