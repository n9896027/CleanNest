# 架构与安全边界

## 主要层次

```text
SwiftUI 界面
    ↓ 用户明确操作
AppLifecyclePolicy：冷启动与各页面允许的工作负载
    ↓ 单槽任务、进入页面加载、离开页面取消/延迟释放
AppStore 状态与任务编排
    ├─ AgentWorkspacePresentationState：Agent 页独立发布域
    ├─ CleanNestScanner.xpc：可丢弃的独立文件扫描进程
    │       ↓ 版本化 JSON Data，只返回进度与完整结果
    │  CleanNestCore：扫描、解码、安全策略、进程复核、SQLite 指标
    ├─ CleanNestMutation：仅 GUI 链接的废纸篓移动能力
    ├─ Mole CLI：独立本地子进程，可替换、可升级
    ├─ oMLX / mlx_lm.server：仅 127.0.0.1 的可选本机解释服务
            ↓ 严格 JSON 校验
       只读建议，不产生执行能力
    ├─ LocalModelRuntimeDiscovery：进程 + launchd + TCP 监听 + 平台 API 的只读运行证据
            ↓ 自有实例直接正常停止；外部实例先风险确认并复核精确身份
       SIGTERM 优先；精确用户 LaunchAgent 可确认后 disable + bootout，并可重新启用
    └─ CleanNestMCP：stdio only 的独立只读进程
            ↓ 只读打开本机快照与 SQLite WAL
       无 HTTP、无写工具、无文件正文

macOS ServiceManagement
    └─ CleanNestLoginItem：登录后以 --menubar-only 打开主 App
```

- `Sources/CleanNest`：窗口、视图、App 生命周期、本机 MLX 进程管理和用户操作编排。
- `Sources/CleanNestCore`：不依赖 SwiftUI 的模型、扫描器、命令运行器、JSON 解码、AI 协议和安全策略。
- `Sources/CleanNestMutation`：原子、排他的 App 废纸篓移动实现；只由 GUI 与测试链接，MCP 不依赖该模块。
- `Sources/CleanNestSelfTest`：跨模块集成自检，包括进程树终止和协议绕过回归。
- `Sources/CleanNestMCP`：换行分隔 JSON-RPC 的 stdio 入口；协议和工具实现位于 Core。
- `Sources/CleanNestLoginItem`：嵌入 `Contents/Library/LoginItems` 的极小登录项；只负责静默打开主 App，不采样、不持有文件权限。
- `Sources/CleanNestScanner`：嵌入 `Contents/XPCServices` 并独立签名的扫描服务；只接受内部版本化扫描协议，没有删除、进程控制或网络能力。
- `Tests/CleanNestCoreTests`：可定位的确定性单元测试。
- `build.sh`：编译、生成图标、原子组装 App Bundle、签名并验证指定要求。

## 页面生命周期与内存边界（0.7.0）

1. 冷启动只允许菜单栏原生监测、Mole 探测、指标存储准备和用户启用的本地模型运行时发现；不会加载指标图表、进程列表、模型目录、完全磁盘访问探测或 Agent 文件级结果。
2. `RootView` 以当前侧栏页面驱动 `AppLifecyclePolicy`。清理、卸载和磁盘页才探测文件访问；系统状态页才加载历史与进程；Agent 页才启动 XPC 遍历和原生开发工具账本；模型/设置页才读取模型目录。
3. Agent 约 20 项高频状态位于独立 `AgentWorkspacePresentationState`，扫描进度不会触发无关页面与菜单栏的 `AppStore.objectWillChange`。冷启动只读取不含路径和动作能力的 `AgentWorkspaceSummary`。
4. 菜单栏、指标、模型运行时和 Agent 监测都使用单一可取消 Task 槽；重新开始前取消旧任务。Agent 监测还要求 App 处于前台且 Agent 页仍为当前页面。
5. 离开 Agent 或系统状态页 15 秒后释放文件级快照、依赖图、开发工具预览、进程列表和图表点；聚合摘要、持久化历史和恢复记录不被删除。
6. `MemoryBudgetCapture` 只在显式测试环境变量存在时运行，以 `task_vm_info.phys_footprint` 记录冷启动、全页巡游和真实 Agent 场景；普通 App 启动不创建报告或自动巡页。

## 任务优先信息架构（0.7.1）

1. 总览任务队列只由已有确定性状态派生：磁盘/内存状态、清理扫描、活动失败、实测文件访问和 Mole 连接。任务按钮只导航、打开详情或运行已有只读扫描，不会因排序而新增自动执行。
2. `CleanNestSettingsSection` 把设置分为七个页级状态。`AppLifecyclePolicy` 只为当前分栏启动必要工作：扫描与隐私运行文件访问实测，本机 AI 运行模型目录、运行时发现和回环健康探测；其他分栏不启动这些工作。
3. 活动明细保存在 `activity.json`，独立累计成果保存在 `activity-lifetime-totals.json`。新的完成/部分完成记录同时追加累计；清空明细只删除前者，累计归零有单独确认入口。首次升级时如果累计文件不存在，仅从现有活动明细重建一次。
4. 可点击卡使用按钮角色、可执行动作和完整语义标签；状态与统计元素合并子元素并以“只读”开头。总览最近结果通过稳定活动 ID 进入对应详情，不依赖列表位置或文本匹配。

## 清理工作台与证据闭环（0.7.2）

1. 每次清理请求都生成 `CleanupScanSession`，同时保存开始/完成时间、耗时、根目录检查结果、有界遍历跳过计数、原始候选类别和证据时间。根目录只保存脱敏显示路径；缺失、不可读、普通文件或符号链接根不会进入枚举。
2. 标准缓存规则与下载/媒体扫描分别收集根和遍历证据，`ScannerWorker` 只在两段都完成后合并为一次可传输响应。取消或 XPC 失败不会发布半份新会话。
3. `CleanupSelectionPolicy` 的全选、清空和反选只作用于明确传入的候选 ID；安装包、归档、截图、媒体与重复项初始不选。处理篮展示候选体积、清空废纸篓后的理论容量、恢复方式和执行前重验数量，不把候选体积写成已释放空间。
4. 个人文件仍通过专用安全通道移入废纸篓。重复候选在执行前重新读取候选与保留副本身份并流式计算两端完整 SHA-256；任何一端变化都拒绝该项。
5. 清理活动的 `CleanupActivityResult` 分别持久化候选体积、成功移入废纸篓体积和操作前后即时 APFS 可用空间差值。差值只是当次观测，不把废纸篓内文件体积或理论容量冒充为已经回收。
6. 磁盘浏览启动根独立固定为启动卷 `/`，卷名由 `FileManager` 读取；“主目录”只作为显式快捷入口，进入页面不会自动开始全盘扫描。

## 扫描与解释数据流

1. 用户选择功能或目录。
2. App 根据路径和完全磁盘访问探测决定是否允许遍历，然后才通过 XPC 发送有界请求。
3. 磁盘浏览和 Agent 工作区均由独立扫描服务运行原生分析器；主 App 不在自身进程内遍历 Agent 目录。磁盘浏览先枚举当前层级，并在每个顶层项目完成后发布部分结果。
4. 15 分钟内仅在有界元数据签名一致时复用缓存；签名包含当前项目和有限直接子项的类型、符号链接、大小与修改时间。深度刷新可绕过缓存。
5. 完整磁盘结果生成有界的文件类型、年龄、来源、用途、可恢复性与增长证据，并用 Treemap 与决策中心展示。
6. 用户可在决策中心把条目标记为待清理复核、保留或稍后处理；决定以条目不可逆指纹保存在本机。只有确定性引擎已经判为可复核且非高风险的条目，才允许标记为待清理复核；决定本身不产生选择或删除能力。
7. 用户主动请求 AI 时，客户端构造脱敏、限量、token 化快照。
8. 回环模型返回严格 JSON；客户端验证完整字段、token、枚举、大小和语义边界。
9. UI 展示经本机规则校正后的说明。模型没有执行通道。

增量索引最多保存 12 个根的哈希身份、条目相对身份、签名、大小和计数，不保存完整绝对路径或文件正文。只有扫描与证据两阶段都完成时，App 才会同时替换报告与完成元数据。取消、XPC 中断或服务崩溃会保留上一次完整结果；App 不会回退到主进程扫描。客户端关闭连接后，扫描服务主动退出，下次扫描由 macOS 重新启动。

## Agent 工作区数据流（0.7.0）

1. 主 App 从内置目录或已验证的同签名者规则包取得 `AgentRuleCatalog`；扫描协议 v4 把这份值类型规则送入独立 XPC，并要求清理响应携带完整扫描会话。XPC 只在通过路径边界验证的根下使用 `FTS_PHYSICAL` 读取文件类型、分配块、逻辑大小、修改时间和设备/文件号；不跟随符号链接，不打开会话正文、代码或凭据内容。
2. 扫描前用当前用户的 `lsof` 打开文件表定位活跃文件；即使未在表内，近 15 分钟仍有写入的文件也会锁定。打开文件探测失败时明确降级，不会把未知活跃状态冒充为安全。
3. 扫描最多处理每个 Agent 600,000 个目录项。读取失败、取消或达到上限的分组标记为不完整，其预览体积强制为零；上一次完整界面结果和基线保留。
4. App 只在整次结果完整时写入 `agent-workspace-observation.json`，其中仅有时间、Agent/分类 ID 与分配块体积，没有绝对路径；同时写入更小的 `agent-workspace-summary.json`，后者只含供应方聚合数量、体积、活跃项数和摘要文字。后续扫描用观察基线识别明显增长，冷启动只读取聚合摘要。
5. 扫描器只为二进制硬编码支持的 Codex/Claude 缓存、临时文件和日志中的静置普通文件生成有界执行令牌；令牌绑定供应方、分类、路径、设备号、文件号、所有者、逻辑/分配大小与纳秒级修改时间。外部规则、新 Agent、会话、索引、记忆、凭据、运行时和虚拟机没有执行令牌。
6. 用户手动选择后，GUI 专用 `CleanNestMutation` 再读取打开文件表并复核全部身份。它在同一数据卷的 `Application Support/CleanNest/AgentRecovery` 建立权限为 `0700` 的事务目录，以硬链接作为无复制备份源，使用固定参数调用系统 `ditto` 创建 ZIP，并要求 `unzip -tqq` CRC 校验成功。
7. 备份完成后再次复核打开状态与身份，才以排他原子重命名把原件移入事务区；部分失败会反向回滚。完整压缩包成立后才释放事务原件，并保存含原路径的本机恢复清单。恢复不会覆盖 Agent 后来重建的同名文件。
8. 操作记录分别保存 Agent 目录减少量、压缩包分配块和前后文件系统可用空间；只把正向 APFS 实测差值计入累计空间成果。扫描 XPC 与只读 MCP 不链接 `CleanNestMutation`。
9. 开发工具账本只调用供应方原生接口：Git/Hugging Face 必须先 dry-run，Docker/npm/pip 在没有等价预演时只读。Hugging Face 检查强制离线并关闭遥测。
10. 运行关系图在主 App 内有界读取当前用户进程、`launchctl list`、已安装 App 元数据与 TCP 套接字。Agent/应用/数据/进程/守护边按精确身份建立；Agent 到模型的边只有在该 Agent PID 到模型监听端口存在 `ESTABLISHED` TCP 连接时成立。模型仅运行或端口字符串相同不会生成推断边。

## 下载、媒体与重复文件数据流

1. 用户在“清理空间”启动扫描后，主 App 建立独立 XPC 会话；服务内的 `DownloadMediaScanner` 有界枚举下载、桌面、文稿、图片、影片与音乐，并跳过隐藏项、符号链接、包内容和未完整下载的云端占位文件。
2. 下载目录中的安装介质与压缩档按扩展名分类；ZIP 只读取末尾有限字节中的中央目录，不解压文件。图片、影片与音频只有同时超过体积和 14 天未修改门槛时才成为手动复核候选。
3. 重复检测先按逻辑大小分组，再用首尾各 64 KiB 的临时指纹排除明显不同的文件；只有局部指纹一致时才使用可复用 POSIX 缓冲区流式计算完整 SHA-256。局部指纹永远不作为重复证据；哈希和文件内容只存在于当前扫描内存，不进入 AI、历史记录或索引。
4. 每个重复组按稳定的目录优先级、深度、修改时间和路径选定一份保留副本；其他副本携带候选、保留副本和摘要证据，但仍不自动勾选。
5. 执行时使用个人文件专用安全通道，核对允许根、普通文件身份和扫描证据。重复副本会重新计算两端完整 SHA-256；任何移动、替换或内容变化都会拒绝该项。
6. 成功项仅由系统移入废纸篓。界面展示的是候选体积，实际 APFS 释放空间只有在用户之后清空废纸篓才能确定。

## 本机学习数据流

1. 用户提出“以后优先清理 / 保留”，或一次安全清理成功时，只生成或加强待审核提案；不会立即影响排序。
2. `EvolutionMemory` 将候选项类型、规范化名称与路径的不可逆指纹作为稳定键，不写入候选项完整路径；模型 ID 同样只保存不可逆的稳定哈希。
3. 用户在规则审核台明确启用后，规则才影响后续排序和标记；规则可暂停、重新启用或撤销。
4. 成功移到废纸篓只增加证据次数，永远不能覆盖明确的保留判断，也不能自动启用规则。
5. 记忆不会改变勾选状态、安全策略或执行能力；用户可审计事件并清空整个记忆文件。

## 本机状态数据流

CleanNest 有两条相互独立的状态链路：

1. `NativeSystemMonitor` 按用户选定的 1/2/5/10 秒频率，从 Mach、`getifaddrs`、启动卷容量、IOBlockStorageDriver、IOAccelerator、IOPowerSources 和只读 AppleSMC 获取短期样本，驱动顶部菜单栏与系统状态页的实时仪表。每轮先合并历史、诊断和容量变化，再发布一个一致样本，避免同一轮重复刷新界面。这条链路不需要 Mole，只在内存中保留最近 90 个样本，退出 App 即停止。
2. Mole 状态与原生内存探测合并为单次 `SystemSnapshot`。App 运行时每 60 秒写入 `metrics.sqlite3`，默认保留 30 天，用于长期趋势。

温度、GPU 和风扇计数只在系统返回有效值时显示，缺失保持为空，不伪造为零。AppleSMC 适配层不包含任何写方法，因此不能改变风扇模式或转速。MCP 只读打开历史 WAL 数据库，不创建表、不修剪数据。详见 [METRICS.md](METRICS.md) 与 [MCP.md](MCP.md)。

## 本地模型运行数据流

1. `LocalModelRuntimeDiscovery` 按 10–60 秒自适应间隔从系统 `ps` 与 `lsof` 读取模型相关进程、RSS、启动时间和 TCP 监听：用户停留在模型页时最快，App 非活跃、菜单栏模型状态关闭或没有运行实例时自动降频。同时读取 `launchctl list` / `print-disabled` 与标准 LaunchAgents / LaunchDaemons 的有限元数据。完整命令行和 plist 参数只在本次内存分类中使用，不进入公开模型或持久化；环境变量不读取。
2. 发现层仅探测 oMLX、MLX-LM、Ollama、LM Studio、llama.cpp 的标准回环端口、已识别进程端口和用户明确配置的回环端点，不扫描局域网。
3. OpenAI 兼容平台读取 `/v1/models`，Ollama 读取 `/api/tags` 与 `/api/ps`。只有 API 返回可用短 ID 才标记健康，仅有 PID/端口时保持待确认。
4. 发现层按 launchd 当前 PID 把模型进程与守护标签交叉对齐；未运行但仍有 plist 的模型守护也以“未运行 / 已停用”实例显示，避免停用后入口消失。
5. `AppStore` 把发现到的 PID 与 `LocalModelOwnedRuntime` 当前 `Process` 身份精确对齐；自有实例一致时可直接正常终止。普通外部实例只在具备足够身份时提供带省略号的风险确认入口。
6. 外部实例确认后必须强制重新发现，并把原快照、刷新快照和即时进程快照的 PID、启动时间、当前用户与可执行文件交叉复核；任一身份变化都拒绝操作。先发送 SIGTERM，3 秒仍存活时才允许用户二次勾选后发送 SIGKILL，不按名称批量结束。
7. 守护停用是独立提交链：再次复核模型进程、标签、`gui/<uid>` 作用域、当前用户所有权、标准用户 LaunchAgents 目录，以及 plist 的设备号/文件号；通过后才用参数数组调用 `launchctl disable` 与 `bootout`。不编辑/删除 plist；重新启用先复核同一文件，再调用 `enable` 与 `bootstrap`。
8. 运行快照、监听地址和推导的内网地址只保留在内存，驱动侧边栏运行中心和独立 `MODEL` 菜单栏状态；活动记录只保留平台、PID 或守护标签与结果，不保存模型 ID、地址或命令。

## 高风险操作边界

- 文件：缓存与残留只接受原白名单根目录的严格后代；个人文件另限于下载、桌面、文稿、图片、影片与音乐中的带身份普通文件。两者都拒绝根目录、受保护路径和符号链接，并只移到废纸篓。
- 手动磁盘决定：只能维持或收紧系统边界；旧的待清理记录在新证据变为受保护或高风险时失效，且永远不能直接触发文件操作。
- 应用卸载：App 本体必须位于标准 Applications 目录；扫描后到执行前复核设备号、文件号与 Bundle ID；当前账户可写时同卷原子移入废纸篓，确需更高权限时才交给 Finder；本体未确认成功前不处理精确 Bundle ID 相关文件。
- 进程：操作前后复核 PID 身份、启动时间和可执行文件，保护系统/关键进程，先正常退出再由用户决定是否强制。
- 权限：只根据实际读取结果分类，不把系统设置跳转当授权成功，也不循环触发访问窗口。
- 网络：AI 端点固定为 IPv4 loopback HTTP，禁用代理、Cookie、凭据存储、缓存和重定向。
- 模型运行时：只读发现不访问其他局域网设备；启动和 launchctl 参数均为固定结构化数组，不拼接 shell；自有实例按持有身份正常终止；外部实例先复核进程身份；守护停用只允许当前用户标准 LaunchAgent 并复核标签、作用域与 plist 文件身份，系统/其他用户守护只读，配置不删除且可恢复。
- 更新检查：仅在用户点击后通过临时无 Cookie 会话读取 GitHub 公开的最新正式 Release；限制响应大小、验证语义版本和官方仓库 HTTPS 页面，只提供浏览器跳转，不下载或替换 App。
- MCP：只允许本机 stdio，工具集合固定为只读查询；不暴露文件处理、进程结束或设置修改。

## 发布信任边界

CI 的 ad-hoc 签名只证明 Bundle 结构可构建，不代表发布者身份。面向普通用户的二进制必须使用 Developer ID、Hardened Runtime、Apple 公证和可验证校验值。流程见 [RELEASING.md](RELEASING.md)。
