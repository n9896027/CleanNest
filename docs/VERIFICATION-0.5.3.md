## oMLX 真机验收

- 发现平台：oMLX。
- 服务返回的主模型短 ID：`Qwen3.8-27B-Uncensored-8bit`。
- 用户从上一版关闭 PID 46159 后，oMLX 于 2026-08-24 18:51:44 被重新拉起为 PID 11394，证明旧操作只结束了子进程，没有停用上级管理器。
- 当前进程：PID 11394，`omlx-server`；父进程为 PID 1 `launchd`。
- 监听：`127.0.0.1:8080`，界面正确标记为“仅本机”。
- 证据链：进程 + launchd 守护 + 监听端口 + 平台 API + 用户配置。
- `launchctl list`、plist 与 `brew services info omlx --json` 一致指向 `homebrew.mxcl.omlx`；配置位于 `~/Library/LaunchAgents/homebrew.mxcl.omlx.plist`，同时设置 `KeepAlive=true` 与 `RunAtLoad=true`。
- 重启后的 `/health` 可读；验收时返回模型数 2、已载入模型数 0、引擎模型内存 0，CleanNest 没有把旧的 30.98 GB 状态沿用为当前事实。
- 该进程不是由 CleanNest 启动；界面会提供“停用守护并关闭…”入口，展示 PID、守护标签、plist 来源与自动重启风险，并要求勾选确认。验收未点击最终停用，不为开发测试再次中断用户服务。
- 正常结束能力由单元测试启动的独立 `/bin/sleep` 子进程完成真实验证：取得精确快照后发送 SIGTERM，结果为 `terminated`，没有按名称或模糊匹配操作。
- DFlash2 仅作为平台返回的可用模型短 ID 显示；当前健康 API 没有提供可验证的“已启用”字段，CleanNest 没有猜测它的运行状态。

## Ollama 故障边界验收

- 确认 `127.0.0.1:11434` 未被占用后，临时启动已安装的 Ollama 0.20.0-rc1 空服务，未下载或加载模型。
- CleanNest 自动发现 Ollama 进程与端口，读取 `/api/tags` 与 `/api/ps`。
- 由于 `/api/ps` 没有正在加载的模型，界面显示“待确认”和“模型短 ID 尚未确认”，没有冒充健康。
- 验收后使用该测试会话的正常终止精确关闭 Ollama；11434 端口已释放，CleanNest 在下一轮发现中移除该实例。
- 全程中 oMLX PID 46159 和 `127.0.0.1:8080` 保持健康。

- 菜单栏已显示紧凑双层 `1 / MODEL` 状态，与 0.5.2 的 CPU / MEM / TEMP 等指标保持同一密度。
- 菜单栏开关为真实状态；开启时创建独立状态项，不需要终端。
- Build 17 真机实时仪表与菜单栏弹窗均已核对：内存完整显示已用量/总量，网络完整显示下载/上传及物理接口合计，不再以省略号隐藏关键数值。
- Build 17 真机确认网络仪表已出现有效的上下行 SF Symbol，不再渲染为空白。
- 温度仪表同时显示 AppleSMC CPU 温度与 IOKit 电池温度；电池温度按同一 2 秒节奏更新，旧的页面底部单次采样提示已移除。
- 设置页的指标预览也改为独立换行展示，窄卡片不再挤压或截断可用性说明。
- 活动记录以当前保留的 48 条真实记录聚合出 13.23 GB 处理空间、20 个清理项目、11 个已卸载 App 与 39 次有成果操作；界面明确说明移入废纸篓不等于 APFS 空间已释放，清空历史会让统计归零。
