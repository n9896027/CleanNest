# CleanNest 0.5.4 本机验证报告

验证日期：2026-08-26
版本：0.5.4（Build 18）
范围：下载项、个人媒体、精确重复文件、清理界面与执行前安全边界

## 结论

0.5.4 的源代码、确定性测试、当前 Mac 真实只读扫描、SwiftUI 界面和本地签名 App 均已通过本轮验证。下载、媒体与重复文件不会自动勾选；本轮没有移动或删除任何真实个人文件。

这不等于已经验证“清空废纸篓后的 APFS 实际释放空间”，也不等于提供相似照片或 Photos 图库清理。当前重复检测只承诺字节完全一致。

## 当前 Mac 真实只读扫描

从签名构建的 CleanNest 清理空间页手动启动扫描，界面返回：

- 检查 6,253 个本地普通文件；未达到文件上限或哈希候选上限；未触发云端文件下载。
- 下载项 12 个：1 个安装包、11 个普通归档。
- 大型旧媒体 424 个：图片 13 个、视频 3 个、音频 408 个。
- 完全重复 76 组、129 个可选副本，候选分配体积约 3.75 GB。
- 个人下载、媒体与重复项全部保持未勾选；底部 4 个已选项目仅来自旧的低风险可重建缓存建议，约 1.42 GB。
- 超过 24 项的分类默认折叠；重复分组可展开，并显示 SHA-256 已验证、保留副本和执行前复核说明。
- 使用 English 启动参数实际打开清理页，标题、证据说明、扫描开关、搜索框和安全文案均显示为英文；构建产物中的繁體中文对应键也已导出并抽样核对。

同一文件可以同时是下载归档或媒体，又是某组重复副本，因此证据卡的分类数量不能相加。列表保留原始类型，并为重叠项目增加“字节完全相同”标记。

## 确定性测试

- `swift test`：78 项通过，0 失败。
- `swift run CleanNestSelfTest`：全部检查通过。
- 下载与媒体专项测试覆盖：嵌套安装包、安装型 ZIP、普通 ZIP、图片/视频/音频门槛、精确重复保留策略、下载与重复双重分类、文件替换拒绝和 ZIP 中央目录解析。
- 安全策略测试确认：普通缓存接口仍拒绝图片目录；只有携带扫描身份的个人文件候选才能进入专用通道，缺少证据即拒绝。

## 执行前控制

- 枚举跳过隐藏项、符号链接、包内容和未完整下载的 iCloud 占位项目。
- ZIP 只读取尾部有限字节中的中央目录，不解压内容。
- 重复检测先按逻辑大小分组，只对至少 1 MB 的同尺寸文件流式计算完整 SHA-256；文件字节和哈希不上传、不进入 AI，也不持久化。
- 下载、媒体和重复候选永不自动勾选。
- 个人文件执行前复核设备号、文件号、大小和修改时间；重复项还会重新计算候选与保留副本的完整 SHA-256。
- 任一路径、身份或内容发生变化时，该项停止；成功路径也只允许移到 macOS 废纸篓。

## 构建与签名

- `build.sh release` 使用本机 `Yuan OS Local Code Signing` 身份完成 Hardened Runtime 签名。
- 主 App、登录项与只读 MCP 均通过严格磁盘签名和 Designated Requirement 验证。
- App、登录项和 MCP 版本均为 0.5.4；主 App Build 为 18。

本地签名用于保持当前 Mac 的 TCC 代码身份稳定，不是 Apple Developer ID，也未经过 Apple 公证，不能作为面向公众的可信安装包发布。

## 尚未覆盖

- 没有在真实个人文件上执行移到废纸篓；本轮只进行了真实只读扫描，执行拒绝路径使用临时测试文件验证。
- 不识别视觉近似照片、转码后相似视频或音频指纹；只识别完整 SHA-256 相同的文件。
- 不进入 Photos、iMovie、Logic 等包或媒体资料库内部；应由所属 App 管理的内容保持跳过。
- 默认最多检查 25,000 个文件、3,000 个哈希候选并限制目录深度；达到上限时界面会明确标为部分结果。
- 候选体积不等于 APFS 实际释放量；文件进入废纸篓后仍占空间，只有用户清空废纸篓后才能实测释放量。
