# CleanNest 0.5.2 本机验证报告

记录日期：2026-08-24

状态：0.5.2（Build 12）的紧凑菜单栏、原生指标、登录启动与本机发布构建已通过当前 Mac 的即时验收。48 小时耐久测试尚未完成，因此不把长期稳定性写成已验证事实。

## 测试环境

- Apple Silicon（arm64）
- macOS 26.5.2
- Xcode 26.6（Build 17F113）
- App、只读 MCP 与登录项版本：0.5.2（Build 12）

## 自动化结果

- Swift 单元测试：56 / 56 通过，0 失败。
- `CleanNestSelfTest`：全部检查通过。
- Release App 构建通过；主 App、`CleanNestMCP` 与嵌入式 `CleanNestLoginItem.app` 均通过严格签名验证。
- `Info.plist` 与 Git 空白错误检查通过。

## 菜单栏真机验收

- 默认使用双层紧凑布局：上层显示数值，下层显示 `CPU / MEM / TEMP / NET / SSD / GPU / FAN` 短标签。
- 七项指标在当前 5K 菜单栏中同时可见；设置中的顺序与菜单栏从左到右的顺序一致。
- 设置页实测显示 2 秒刷新、摄氏温度、物理网卡合计，并明确提示 7 项已使用紧凑布局。
- 实际样本可读到 CPU 用户/系统/空闲分解、内存、温度、物理网卡流量、启动卷容量与读写速率、GPU Renderer/Tiler 以及两枚风扇转速。
- `⌘⌥M` 已由 macOS Hot Key API 返回注册成功；自动化界面工具不能发送真正的系统级全局快捷键，因此物理键盘触发仍保留为人工验收项。

## 登录启动真机验收

- 登录项由 macOS ServiceManagement 管理，设置页状态为已启用。
- 手动执行嵌入式登录项后，真实进程命令行为 `CleanNest --menubar-only`。
- 该模式下七项菜单栏指标持续显示，主窗口没有出现；随后已退出后台实例并重新打开普通 App。

## 仍待观察

- 48 小时常驻测试仍需覆盖睡眠/唤醒、显示器重连、网络接口切换、长时间 CPU/内存开销与菜单栏可见性。
- 当前本机构建使用稳定的本地签名身份，不等同于 Developer ID 签名、公证和装订的公开可信安装包。
