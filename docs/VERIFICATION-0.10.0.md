# CleanNest 0.10.0（44）交互重构

日期：2026-09-08。分支：`agent/0.10.0-clarity`。
基线：保留 Claude 0.8.4 及上一轮尚未提交的 0.9.0；本次未提交、推送、合并或发布。

## 设计目标

用户打开 CleanNest 时先看到当前对象和下一步；需要解释、证据或低频工具时再展开。
原生半透明工作台：克制的层级和颜色，明确可点击控件，不再用整屏同等权重的卡片表达所有信息。
采用本地 `claude-inspired-ui-design` skill 的任务层级、真实状态与输入验证规则。沿用 SwiftUI / AppKit 和现有状态源，没有安装其他 skill 或新增依赖。

## 功能保留对照

| 栏目 | 默认主任务 | 保留的辅助能力与入口 |
| --- | --- | --- |
| 总览 | 下一步、可点击状态、常用任务 | 最近操作与累计成果展开查看 |
| 清理空间 | 扫描、筛选、勾选、处理栏 | 扫描选项、AI、证据展开；40 项分页、媒体、重复文件、挂载安装介质、偏好和确认流程保持 |
| 应用卸载 | 列表选择 → 私有文件预览 | 宽窗口双栏，窄窗口单栏返回；身份、共享/系统只读项、失败重试、管理员认证与废纸篓确认保持 |
| 磁盘浏览 | 先看空间 / 处理建议 / 核对详情 | 三种占用视角、手动决策、账本、变化、结构图、AI、深度刷新和系统数据清单均可达 |
| 系统数据 | 搜索与大项用途 | 展开统计口径、文件计数、最近写入和处理影响；Finder 与原管理入口保持 |
| Agent 工作区 | 选择助手 → 分类占用 → 选择处理范围 | 工具账本、规则、归档建议、备份恢复、依赖关系、活跃保护均保持 |
| 本地模型 | 运行状态、实例和启停 | 服务详情、连接关系、性能测试、历史、外部停止与精确守护控制保持 |
| 系统状态 | 实时 / 内存进程 / 趋势告警 / 设备 | 全部指标、电池诊断、参考评分、进程组与正常/强制退出确认均保持 |
| 系统维护 | 选择症状 → 诊断 → 单项确认 | 四种维护任务、效果说明、风险和最近结果保持 |
| 清理习惯 | 待确认建议 | 已启用习惯、试用、暂停、撤销、模型反馈、历史与重置展开可达 |
| 活动记录 | 搜索和记录详情 | 类型/结果/时间筛选、累计统计、导出、清空、废纸篓和恢复入口保持 |
| 设置 | 固定分类 → 当前设置 | 七个原分类全部保留，草稿保存、连接测试、权限检测和危险重置确认不变 |

全局搜索只是导航；不自动执行命令、发送提示词或处理文件。导航历史仅保留当前窗口最多 40 个栏目，不保存私密文件路径。

## 边界

- 本轮不执行真实文件清理、App 卸载、进程结束、模型启停或维护重启来测试 UI；危险动作测试止于确认前或取消。
- 原生 macOS App，无移动端；不宣称浏览器 WCAG、VoiceOver、48 小时常驻或 Intel 实机验收。
- 返回 / 前进按钮已实测；对应 ⌘[ / ⌘] 在源码与单元测试中核对，但自动化工具不支持发送方括号按键，未宣称这两个快捷键已完成实机按键验收。
- 原有菜单栏采样、AppStore 后台生命周期与安全执行后端未因 UI 折叠而替换；本轮不是全应用状态管理架构重写。
- 只有本机稳定签名，不是 Developer ID 分发签名，也未经 Apple 公证。
