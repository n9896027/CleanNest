# CleanNest 0.7.0–0.7.9 路线图

状态：计划  
基线：0.6.5（Build 26）  
原则：每个小版本解决一个可见问题，不把十个版本写成一次无法验收的重构。所有规划以 [0.6.5 全栏目审计](AUDIT-0.6.5.md) 为证据基线。

## 总目标

0.7 系列不再以“增加更多卡片”为进化方式，而是完成五件事：

1. 让常驻 App 真正轻量，只为用户当前任务付出计算与内存成本。
2. 把信息展示变成“发现 → 判断 → 预览 → 执行 → 验证 → 恢复”的真实任务。
3. 把设置、系统状态、Agent 和本地模型中重复的信息归一。
4. 建立可量化的内存、无障碍、本地化和长时稳定性门，而不是只看单次绿色测试。
5. 在资质可用时建立 Developer ID + 公证的可信分发链；资质不可用时诚实停在源码发布。

## 统一不变边界

- 不把 AI 变成文件、进程、权限或守护的执行主体。
- 不为了“一键”扩大路径白名单、模糊匹配相关文件或批量结束进程。
- 不直接修改 Agent 私有会话索引、记忆、凭据或未公开数据库。
- 不扫描局域网模型服务，不把端口存在误报为模型健康或 Agent 实连。
- 不发布未签名、未公证却面向普通用户的 App 安装包。

## 版本序列

### 0.7.0 — 轻量核心与页面生命周期（P0）

**用户结果**：只打开菜单栏或总览时，CleanNest 不再默认扫描所有 Agent 和构建所有重型页面；页面离开后内存可以回落。

范围：

- 将 121 个 `@Published` 的单一 `AppStore` 按监测、清理/磁盘、Agent、模型、设置/活动分成有界状态域，或建立等价的精确发布层。
- 把 Agent 扫描改为进入页面、用户刷新或明确后台预算时才运行；启动优先读取上次聚合快照。
- 长列表改用惰性容器和有界分页；页面离开时释放巨型快照、图层和短时图表。
- 添加启动、全页巡游、Agent 扫描、重复扫描和 60 秒稳定后的自动内存基线。
- 建立页级辅助功能烟测，首先拦截“本机学习内容不可读”这类回归。

验收门：

- 冷启动进入总览时不启动 Agent XPC 遍历。
- 当前测试 Mac 上，冷启动 15 秒后 physical footprint 不高于 220 MiB；逐页巡游后等待 60 秒不高于 350 MiB；非扫描交互峰值不高于 650 MiB。
- 开关菜单栏、离开 Agent/系统状态/活动页不留下重复采样 Task。
- 安全策略、文件令牌、XPC 协议和执行行为不变。

### 0.7.1 — 信息架构、总览与设置分层（P0/P1）

**用户结果**：打开 App 后先看见“现在最值得做的 1–3 件事”，而不是各模块的状态摘要；设置不再是一条超长页。

范围：

- 总览增加统一任务队列，每项显示来源、最后验证时间、影响、下一步和为什么现在值得做。
- 设置分为常规、菜单栏、扫描与隐私、本机 AI、历史与存储、高级、关于；本地模型的日常控制返回运行中心。
- 活动记录增加类型、结果、时间过滤和搜索；累计成果与可清空的明细解耦。
- 所有有卡片外观的元素要么是按钮，要么明确标注只读，不再依赖用户猜测。

验收门：

- 从总览到任一建议任务不超过两次点击。
- 设置的任一关键项可通过页级导航直达，不需要翻过无关卡片。
- 每个最近结果可追溯到活动详情，统计不会因清空明细意外归零。

### 0.7.2 — 清理工作台 v2（P1）

**用户结果**：一次扫描得到可理解的“处理篮”，截图、安装包、归档、媒体和重复组可批量复核，但默认保持安全。

范围：

- 扫描会话显示已检查根、文件数、跳过原因、候选类别、耗时和证据时间。
- 独立的处理篮统一显示已选体积、预计余量、恢复方式和执行前必须重验的证据。
- 截图支持可见批量全选/反选；媒体先按时间、体积和类型聚类；重复组始终显示保留副本。
- 个人文件继续默认不勾选；批量动作只改变选择，不直接执行。

验收门：

- 不完整云端项、符号链接、包内容和根目录继续失败关闭。
- 重复执行前必须重算候选和保留副本的完整 SHA-256。
- 活动记录分开候选体积、移入废纸篓体积和 APFS 实测变化。

### 0.7.3 — 应用卸载与依赖地图（P1）

**用户结果**：卸载前能看懂 App 本体、它的精确相关文件、登录项、用户守护和扩展之间的关系，认证取消或失败也不会留下半套操作。

范围：

- 用 Bundle ID、代码签名、稳定路径和 macOS 注册元数据建立只读依赖图。
- 区分 App 所有、共享组、系统管理和无法证明归属的项目；后两类保持只读。
- 统一“请求 App 退出 → 身份重验 → 系统认证 → 确认废纸篓 → 相关文件 → 最终复核”状态机。
- 结果页显示未完成项、可重试项和 Finder 中的恢复位置。

验收门：

- 高权限卸载覆盖成功、用户取消、认证失败、App 身份变化和 Finder 自动化被拒绝五条真实路径。
- App 本体未确认进入废纸篓时，精确相关文件始终为零变更。

### 0.7.4 — 磁盘决策与增长对比（P1）

**用户结果**：不只看“哪个目录大”，还能看到“谁产生、什么在变大、哪些只能在所属 App 内处理”。

范围：

- 保留最近两次有界聚合快照，对同一根目录显示增长/缩小/新出现。
- 将空间分布、手动决策和证据明细分成三层；详情面板只聚焦当前目录。
- 建立所属 App/工具证据，能安全跳转时提供“在所属 App 管理”，不给出虚假清理按钮。
- AI 只解释用户选中的有界证据；结果与确定性规则并列，不覆盖手动决定。

验收门：

- 取消、XPC 崩溃、根目录变化和缓存过期均保留上次完整报告，不生成假增长。
- 手动“待清理复核”无法覆盖受保护、高风险或不完整证据。

### 0.7.5 — 系统状态、告警与紧凑菜单栏（P1）

**用户结果**：菜单栏保持 State 式紧凑，异常时知道为什么变色，点开后能找到持续异常的 App 或历史时段。

范围：

- 为温度、电池、内存压力、磁盘余量和风扇相对转速提供保守预设与用户阈值；CPU/GPU/网络繁忙仍不是故障。
- 增加只存本机的告警时间线，记录指标、持续时间、峰值与恢复，不记录网络地址或流量内容。
- 进程先按所属 App 聚合，再按需展开辅助进程；退出风险仍逐个复核。
- 菜单栏建立宽度预算和自动降级顺序；窄屏时保留异常项，不用省略号截断数值。

验收门：

- 菜单栏和弹出面板对每个可用指标有相同的阈值、单位和语义色。
- 风扇告警使用相对最大转速和热状态，不用一个通用 RPM 数字判断所有 Mac。
- 48 小时常驻、睡眠/唤醒、外接屏幕和登录启动流程有可重现证据。

### 0.7.6 — 维护诊断中心（P1）

**用户结果**：不再靠猜测运行维护项；选择症状后先诊断，只在证据支持时执行一项，之后告诉用户问题是否真的恢复。

范围：

- 将 Quick Look、Finder、Dock 和菜单栏任务改为“症状 → 只读预检 → 影响预览 → 执行 → 进程/功能复核”。
- 无法确定的预检不会假装已诊断；仍可由用户确认执行，但必须显示不确定性。
- 增加“最近维护结果”的前后证据，而不是只记录命令返回成功。
- 新增任务只允许可解释、可验证、无文件永久删除的系统级操作。

验收门：

- 每项任务至少有无异常、异常存在、执行成功、执行后未恢复四条测试路径。
- 不使用 `sudo`，不修改 SIP/TCC，不清空系统日志，不把重启服务写成“提速”。

### 0.7.7 — 本地模型运行中心 v2（P1，独特功能）

**用户结果**：一个页面看懂“哪个平台在跑、哪个模型在内存、谁在连它、什么会把它重新拉起”，并可安全启停。

范围：

- 将 CleanNest 的 AI 连接和系统运行时发现合并为“平台 → 服务实例 → 模型短 ID → 客户端连接 → 守护”。
- oMLX/MLX-LM/Ollama/LM Studio/llama.cpp 使用独立、可测试的平台适配器；不支持的 OpenAI 兼容服务只显示通用证据。
- oMLX 始终从 `/v1/models` 选择短 ID；模型文件路径只用于 CleanNest 自启服务，不作为 API `id`。
- 自有进程、普通外部进程、用户 LaunchAgent 和系统/其他用户守护保持四级不同控制权限。
- 加入端口冲突、启动超时、自动拉起、睡眠/唤醒、客户端实连和模型替换的诊断链。

验收门：

- 每个声称“可控”的平台必须有真实“发现 → 启动/已运行 → 健康 API → 正常停止 → 再发现”证据。
- 外部服务执行前仍重验 PID、启动时间、用户、可执行文件和守护文件身份。
- 发现局域网暴露时只做风险说明，不自动修改绑定地址或防火墙。

### 0.7.8 — Agent 工作区与本机学习 v2（P1/P2）

**用户结果**：先看到哪个 Agent 在增长或异常，再进入它的缓存、会话、运行时和依赖；学习规则以类别为主，不被大量文件级提案淹没。

范围：

- Agent 首页只保留总量、变化、活跃保护和异常；单 Agent 详情按类别、文件、运行关系和恢复记录分层。
- 扫描可按 Agent 单独刷新；默认不为未进入页面的 Agent 构建文件级明细。
- 本机学习将文件级提案聚类为“类型 + 位置级别 + 风险 + 时间”规则，支持批量审核、试用、暂停、撤销和过期清理。
- 显示规则对下次排序的真实影响对比；规则继续不改变勾选和安全策略。
- 只有当 Agent 供应方提供稳定、可验证的归档/索引事务接口时才为该适配器开放归档；否则继续只读。

验收门：

- 本机学习页标题、统计、每条规则和操作均进入辅助功能树，键盘可完成审核、暂停和撤销。
- 一万条文件级历史不导致一万个同步 SwiftUI 行。
- 外部规则仍无法扩大任何文件处置权限。

### 0.7.9 — 稳定性、本地化与可信发布候选（P0 发布门）

**用户结果**：0.7 系列不只是本机能跑，而是有可重复构建、升级、回滚、长时稳定和普通用户信任链的发布候选。

范围：

- 建立 0.6.5 → 0.7.x 的设置、指标、活动、扫描索引、学习规则和 Agent 恢复记录迁移/回滚测试。
- 核心 UI 的简体中文、English、繁體中文完整覆盖；日文/韩文不冒充完整，要么达到明确门槛，要么保持 README 级说明。
- 完成主要页面的 VoiceOver/键盘/窄窗口/长文案回归。
- 完成 48 小时常驻、反复睡眠/唤醒、扫描取消风暴、XPC 崩溃、模型服务上下线和低磁盘空间回归。
- 产出与最终提交对应的 SBOM、SHA-256 和构建来源证明。
- 如有有效 Apple Developer Program 资质与本机安全凭据，使用 Developer ID Application、Hardened Runtime、时间戳、Apple 公证、staple/validate 和 Gatekeeper 实测生成安装包；否则发布为明确标注的源码版。

验收门：

- 所有前续版本验收门全部通过，且没有未解释的高危 CodeQL/依赖/凭据告警。
- tag 只指向通过保护检查的 `main` 提交；先核对 Draft Release，不替换公开 tag 或同名资产。
- 应用内“检查更新”只为真实、非 Draft、非预发布的 GitHub Release 报告结果，不把 tag 或 CI 产物冒充正式版。

## 依赖关系

```text
0.7.0 轻量核心
  ├─→ 0.7.1 信息架构
  │     ├─→ 0.7.2 清理工作台
  │     ├─→ 0.7.3 应用卸载
  │     └─→ 0.7.4 磁盘决策
  ├─→ 0.7.5 系统状态
  ├─→ 0.7.6 维护诊断
  ├─→ 0.7.7 本地模型
  └─→ 0.7.8 Agent + 学习
全部通过 ─→ 0.7.9 稳定性与可信发布
```

0.7.0 是后续所有版本的前置。0.7.2–0.7.8 可在 0.7.1 的信息架构稳定后按栏目独立开发，但不应跳过每个版本的性能、无障碍和失败关闭门。0.7.9 只负责收口和发布，不再接受新的大型功能。
