# CleanNest 0.5.0 候选验证报告

记录日期：2026-08-24

状态：本机候选检查和 0.5.0 主实现远程检查通过；手动决策修复仍需通过独立 PR 的远程检查，正式 Release 尚未创建。

## 测试环境

- Apple Silicon（arm64）
- macOS 26.5.2
- Xcode 26.6（Build 17F113）
- 测试对象：Xcode 自带的 Platforms 目录；只读，不包含用户文件或私人文件名

- Swift 单元测试：40 / 40 通过，0 失败（含覆盖率运行）
- `CleanNestSelfTest`：全部检查通过
- String Catalog JSON、Info.plist、构建脚本语法和 Git 空白错误检查：通过
- Release App：0.5.0（Build 9），稳定本机签名、Hardened Runtime、Bundle/MCP 严格签名验证和 MCP discovery smoke test 通过

## 界面验收

使用完全合成、不读取用户活动、学习记录、模型目录或磁盘容量的演示模式检查：

- 总览：版本与 Build、洞察闭环、主任务和下一步均可见。
- 磁盘浏览：常规窗口宽度下为左侧项目、右侧决策证据的主从布局；目录整体处理依然只读。
- 本机学习：仅有合成的 1 条待审核提案和 1 条已启用规则，未混入已有本机记录。
- 系统状态：电池事实、内存中文解释、可退出进程和系统受保护进程均可见。
- 设置：oMLX 请求 ID 为短名 `Qwen3.8-27B-Uncensored-8bit`，并显示健康延迟、首字、完整响应、权重和内存余量提示。
- 活动记录：导出、单独清空和打开废纸篓的边界清晰。

另用当前本机真实元数据进行只读交互验证，不保存或公开含私人文件名的截图：

- 受保护的用户文档条目不能选择“待清理复核”，只能跟随系统、保留或稍后处理。
- `~/Library/Caches` 中由确定性规则判为可复建的缓存条目可以选择“待清理复核”，并能在“我的决定”筛选中单独出现。
- `disk-manual-decisions.json` 的记录数随“跟随建议 → 待清理复核 → 跟随建议”实测为 `0 → 1 → 0`；只保存指纹、决定和时间，不保存完整路径。
- 上述操作未勾选清理候选、未移动废纸篓、未删除文件；测试决定已撤销。

## 仍未放行的门槛

- 手动决策修复的独立 PR 仍需通过双架构 CI、CodeQL 和依赖审查，并在合并后验证 `main`。
- Developer ID、Apple 公证、装订和 Gatekeeper 实测仍属正式二进制发布前置条件。
- 缺少 Developer ID 时，0.5.0 只能发布源码；本机稳定签名不等于可分发的 Apple 可信签名。
